# 管理界面操作

## 打开控制台

安装 SeekMemory Release 插件并在 AstrBot 重载后，从 SeekMemory 插件卡片的插件视图入口打开管理界面。插件配置仍在 AstrBot 配置页维护。直接打开静态 HTML 或运行 pnpm dev:host 不会连接生产插件；开发预览请使用 dashboard 的 Mock 模式。

AstrBot 入口要求宿主提供已登录管理员请求上下文；独立入口使用单独的管理员令牌。管理页可以读取完整记忆和原始来源证据，请仅在可信管理员会话中使用。

## 本机独立控制台

在源码仓库使用 Python 3.10 或更新版本，先构建页面，再启动服务：

```bash
pnpm --dir dashboard install --frozen-lockfile
pnpm --dir dashboard build
export SEEKMEMORY_CONSOLE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
python3 scripts/console_http.py --data-dir ./data/console --port 8766
```

打开 `http://127.0.0.1:8766`，保留默认 API 地址，输入环境变量中的管理员令牌并连接。令牌必须至少包含 32 个无空白 ASCII 字符；令牌只保存在页面内存，刷新、断开或服务更换令牌后需要重新输入。服务仅监听 `127.0.0.1`，不提供远程部署入口。

数据目录包含既有格式的 `memory.db`、`persona_packs/` 和 `run_traces.jsonl`。首次使用建议选择新的目录；已有数据需要先停止其宿主并备份，再离线复制整个数据目录。不要让 AstrBot 或另一独立进程同时管理同一个目录：每个进程持有自己的 active cache，无法同步另一个进程的修改。现有 AstrBot 配置与数据库格式不变。

独立控制台支持记忆列表、详情、人工修订、人格包及召回诊断。它不启动聊天宿主、模型、抽取队列或维护调度；维护按钮显示为不可用。生命周期日志为空；运行轨迹在启动时只读加载所选目录中经过白名单校验的离线 trace。轨迹接口默认按 7 天、最多 5000 条事件筛选内存视图；启动、读取和关闭均不改写原文件，持久化清理由生产者负责。离线替换文件后需重启服务。导入任务状态仍需等待真实的记忆导入 API；人格包导入不提供该任务状态。

开发时运行 `pnpm --dir dashboard dev:standalone`，并给服务增加 `--allow-origin http://127.0.0.1:5176`。在连接页填写 `http://127.0.0.1:8766/api/`。允许来源只接受明确的本机 HTTP origin；默认不开放其他页面来源。退出服务使用 Ctrl+C；重新启动时从环境变量读取令牌，不生成令牌文件。

## 记忆库

- 使用类别、状态、scope、关键词和来源会话筛选记录；详情可查看当前 Artifact、版本、版本级证据、来源和账本。
- 编辑 payload、scope 或 state 时填写修改原因并确认。服务端会按 family 校验并检查 expectedRevision；若其他任务已修改该记录，页面收到冲突后应刷新详情再决定是否重做。
- Forgotten 可通过新修订恢复为 active。Merged 记录不能独立恢复，也不能用编辑伪造 merge 关系。
- 人格时间线可查看历史版本并回滚。回滚会在同一 Persona ID 上创建新 revision，不会删除历史。

## 召回诊断

输入查询、完整会话 UMO 与实际 speaker ID，预览预计组装块、候选与披露决策。诊断复用真实 recall 路径，但不调用模型、不写记忆、不消费 designated 的一次性交付状态。它只检查记忆上下文，不模拟整个聊天模型输出；随机探索可能使不同次诊断的候选有所变化。

## 状态与维护任务

- 状态页展示引擎、账本校验、provider 配置、pending 会话/话题、容量、Dream 与 checkpoint 信息。Provider 检查不会发起模型请求，也不保证网络、额度或模型调用可用。
- **立即抽取**处理已排队话题并可能调用配置的抽取模型；检查 written、skipped、warning 和剩余 pending 数，而不只看任务是否完成。
- **每周整理**执行自我印象汇总、遗忘、合并和人格处理。已 bootstrap 且达到周期的人格可能进行一次受限模型综合；失败时保留当前人格。
- 同时只运行一个维护任务。取消只停止仍在运行的工作，不回滚已经完成的提交。

## 日志与运行轨迹

生命周期日志帮助定位业务阶段、耗时、源码位置和错误类型；它是有界诊断记录，不是完整审计归档。Agent Run Trace 展示请求、召回、工具与发送的关联事件，但不记录消息正文或模型响应。“记忆已注入”只表示内容进入请求上下文，不代表模型实际使用了它。

容量 Trace 是独立的运行时样本。三类观测数据用途不同，不能互相当作业务事实。

在运行轨迹页填写完整运行编号、运行结果和最后更新时间范围后查询；时间采用设备时区，包含起止边界。条件可组合，也可清空。服务器只返回保留窗口内匹配运行的完整可用时间轴；召回标记可以继续筛选当前结果。失败步骤直接来自 error 事件；“上次运行未结束”只说明未记录结束，不代表已知异常原因。部分步骤未保留时页面明确提示不完整。

两个入口使用相同的 `GET manage/traces` 查询契约。例如 `?status=error&since=2026-10-29T00:00:00Z` 选择最后更新在该时刻及之后的失败运行；可再加 `run_id=<32位运行编号>` 精确定位。接口与页面都不要求读取内部业务表，字段白名单与保留限制见[运行时设计](../architecture/modules/runtime.md#运行轨迹事件边界)。

开发态界面、Mock 与构建步骤见 [开发环境与验证](development.md)。

## 人格控制台与记忆星图

侧边栏组织首页、人格工作室、记忆、人物印象、人格商店和 Dream；运行轨迹只在系统的二级菜单中提供入口。
人格工作室可比较历史版本，回滚前展示差异并要求确认及原因。商店区分内置人格包和本地蓝图；安装创建当前人格的新版本，不创建 Source，也不调用模型。导出当前人格只保留蓝图白名单字段，不包含原始对话、来源证据、账本或历史版本。导入和更新只保存文件，安装需要单独确认。

星图用 Canvas 透视投影展示记忆，先筛选再按更新时间取最近 80 条，可切换 40/80/120 条。球面网格是视觉几何，不能当成记忆之间的语义关联；选中记忆后虚线才表示接口提供的关联。可拖动旋转、缩放、悬停预览和点击展开，动画尊重减少动态效果偏好。受保护节点保持遮蔽，须显式打开受保护详情才能读取内容。

生命周期日志每三秒刷新，可暂停、自动跟随及展开详情。开口策略日志中的“允许回复”表示本轮放行，“本轮不回复”表示策略阻止本轮回复；都不代表消息实际发送结果。可在“更多筛选”的状态菜单中筛选这两种记录。
