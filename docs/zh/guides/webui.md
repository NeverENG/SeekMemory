# 管理界面操作

## 打开控制台

安装 SeekMemory Release 插件并在 AstrBot 重载后，从 SeekMemory 插件卡片的插件视图入口打开管理界面。插件配置仍在 AstrBot 配置页维护。直接打开静态 HTML 或运行 pnpm dev:host 不会连接生产插件；开发预览请使用 dashboard 的 Mock 模式。

所有管理 API 都要求宿主提供已登录管理员请求上下文。管理页可以读取完整记忆和原始来源证据，请仅在可信管理员会话中使用。

## 记忆库

- 使用类别、状态、scope、关键词和来源会话筛选记录；详情可查看当前 Artifact、版本、版本级证据、来源和账本。
- 编辑 payload、scope 或 state 时填写修改原因并确认。服务端会按 family 校验并检查 expectedRevision；若其他任务已修改该记录，页面收到冲突后应刷新详情再决定是否重做。
- Forgotten 可通过新修订恢复为 active。Merged 记录不能独立恢复，也不能用编辑伪造 merge 关系。
- 人格时间线可查看历史版本并回滚。回滚会在同一 Persona ID 上创建新 revision，不会删除历史。

## 召回诊断

输入查询、完整会话 UMO 与实际 speaker ID，预览预计组装块、候选与披露决策。诊断复用真实 recall 路径，但不调用模型、不写记忆、不消费 designated 的一次性交付状态。它只检查记忆上下文，不模拟整个聊天模型输出；随机探索可能使不同次诊断的候选有所变化。

## 状态与维护任务

- 状态页展示引擎、账本校验、provider 配置、pending 会话/话题、容量、Dream 与 checkpoint 信息。Provider 检查不会发起模型请求，也不保证网络、额度或模型调用可用。
- **立即抽取**处理已排队话题并可能调用配置的抽取模型；检查 written、skipped、warning 和剩余 pending 数，而不只看任务是否完成。
- **每周整理**执行自我印象汇总、遗忘、合并和人格处理。已 bootstrap 且达到周期的人格可能进行一次受限模型综合；失败时保留当前人格。
- 同时只运行一个维护任务。取消只停止仍在运行的工作，不回滚已经完成的提交。

## 日志与运行轨迹

生命周期日志帮助定位业务阶段、耗时、源码位置和错误类型；它是有界诊断记录，不是完整审计归档。Agent Run Trace 展示请求、召回、工具与发送的关联事件，但不记录消息正文或模型响应。“记忆已注入”只表示内容进入请求上下文，不代表模型实际使用了它。

容量 Trace 是独立的运行时样本。三类观测数据用途不同，不能互相当作业务事实。

开发态界面、Mock 与构建步骤见 [开发环境与验证](development.md)。
