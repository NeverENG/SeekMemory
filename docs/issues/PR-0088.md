# PR-0088: Independent persona lifecycle verification

Status: draft (test/verification only).

Base: `main` @ `371eeb5`. Builds on #84/#85/#87, on the service-layer split
(#99/#101: `services/*`, `tests/layers.py`, `scripts/run_tests.py`) and on #102
(persona injection is no longer truncated to the per-memory character cap). The
verification suite was rebased and re-run on this base; no older `main.py`/`DB`
entry points are used.

## Scope

- Adds `tests/test_persona_lifecycle_contract.py` for the verification-matrix gaps:
  one model call per cycle, default 7-day interval, evidence privacy (private/secret/
  raw Source), no new Source rows, prompt hygiene and size limits, response field
  limits, rollback validation/provenance/recall, CAS concurrency and restart recovery.
- Extends `tests/test_persona_long_horizon.py` into the issue's 90-day deterministic
  simulation: checkpoints at day 7/30/60/90, seed and synthesized rollbacks, three
  store/cache restarts, one concurrent weekly attempt, per-checkpoint recall and
  prompt-privacy assertions.
- Registers the new file in the `unit` layer (`tests/layers.py`).
- Reuses the existing suites (`test_persona.py`, `test_persona_bootstrap.py`,
  `test_persona_synthesis.py`, `test_persona_synthesis_edges.py`) instead of copying
  their assertions.

No production behavior change in this PR.

## Long-horizon simulation

`tests/test_persona_long_horizon.py` uses a fake clock, a fake model and real
repositories/cache:

- 90 simulated days, one weekly maintenance run per day;
- checkpoints at day 7/30/60/90: exactly one active persona, stable id, monotonic
  revision, `corpus_count`/`corpus_hash` preserved, no `corpus` on dream revisions,
  recall injects the current persona, synthesized rollback and continued evolution stay
  on the same lineage;
- rollbacks: seed at day 30/60, synthesized at day 75;
- restarts: day 30/60/90 (store closed and reopened, cache reloaded);
- one concurrent weekly attempt at day 45: exactly one commit, the other CAS-fails;
- private and secret memories added at day 50 never appear in any captured prompt;
- measured runtime: **0.26 s** (target < 10 s).

## Findings

1. **Seed rollback restores the full corpus on a later revision.** `trusted_self_persona`
   accepts a seed payload only when corpus is absent with zero count/hash, or present
   with matching count/hash. Rolling back to the seed revision therefore re-materializes
   `corpus` in the new revision. "Corpus only on the initial revision" holds for
   synthesized revisions; the seed case is pinned by
   `test_rollback_to_seed_restores_a_trusted_seed_payload`. A follow-up decision
   (relax trust to allow count-only seed revisions, or strip corpus and accept untrusted
   history) belongs with #92 or a dedicated issue.
2. **HTTP admin auth for rollback is host-only.** `webui/routes.py` returns 401 before
   dispatch; covering it needs the real AstrBot request context, so it is documented as
   host-only here.
3. **Windows default encoding.** `tests/test_run_trace.py` reads files without an explicit
   encoding, so the unit layer needs `PYTHONUTF8=1` on Windows. Linux CI is unaffected;
   not changed in this verification PR.
4. **CAS behaviour is correct.** A conflicting concurrent synthesis fails cleanly
   (`status=failed`) and leaves one active revision.

## Residual gaps

- Real AstrBot host: rollback route authentication/timeline contract (`tests/test_webui_host.py`).
- Model *quality* drift over months: probabilistic, tracked by #92 and staging probes.
- Natural-language leakage beyond marker strings: covered by boundary assertions, not proof.
