## Changes

- Add a pure `CapacityGovernor` with Source, Pending, Artifact, Context and Trace
  snapshots.
- Add the `extraction_state` table and rebuild pending turns by joining it to
  immutable Source rows.
- Atomically enqueue Source and extraction state, and migrate `pending.json`
  without deleting the original file.
- Integrate pressure decisions with extraction batch sizing, recall degradation,
  capacity maintenance, alerts and Trace trimming.
- Add Artifact expiry handling that only changes lifecycle state.

Not changed: Source semantics, model adapters, disclosure rules, WebUI API
shapes or release packaging.

## Risk and rollback

| risk | impact | mitigation |
|---|---|---|
| Legacy migration moves `pending.json` | operators may expect the old path | file is retained as `pending.json.migrated` |
| Capacity thresholds are defaults in core | tuning requires code/config review | thresholds are centralized in one frozen dataclass |
| Expiry cleanup changes Artifact state | expired data exits recall | Source, versions and ledger remain immutable/auditable |
| Pressure maintenance can merge/forget | lifecycle state changes under load | actions run at most once per hour and use existing DB.commit |

Rollback: revert this branch before merge, or restore the `.migrated` JSON file
and revert the commit. Do not delete Source rows.

## 补充

### 2026-10-22 CI 收集失败（已修复）

CI 的单元测试步骤逐文件执行 `python tests/test_*.py`，`sys.path[0]` 是 `tests/`，
仓库根目录不在导入路径上。新增的 `tests/test_capacity.py` 与
`tests/test_lifecycle.py` 缺少其它测试模块已有的仓库根目录引导，导入
`app` / `core` 时直接 `ModuleNotFoundError`，这是 `test (3.10/3.11/3.12)`
首次全红的原因。两个文件已补上同款引导（`noqa: E402`），
`test` 三个版本与 `frontend-contract`、`build` 在 `4f07424` 全部通过。

### 2026-10-22 宿主集成四例失败（已修复）

真实 AstrBot 容器里 `tests/test_webui_host.py` 的四个用例失败：

```text
test_topics_are_extracted_separately_and_status_counts_turns
test_cancellation_preserves_inflight_and_new_messages
test_failed_session_does_not_block_other_ready_sessions
test_session_cap_and_new_messages_survive_success
```

根因是 DB 模式下 `Buffer.add()` 按 `source_id` 去重，而宿主侧调用
`buffer.add(umo, text, sender)` 不传 `source_id`：所有这类 turn 的
`source_id` 都是空串，于是被合并成一行，`topics()`、`mark_succeeded()` 和
批次计数全部失真。

修复（`perceive/buffer.py`）：

- DB 模式且调用方未给 `source_id` 时，用 `make_source_id(...)` 生成 id（
  `at` 为空时补当前时间），并经 `enqueue_extraction()` 原子写入 Source 与
  `extraction_state`；
- 去重只针对非空 `source_id`（`_unique_by_source`），空 id 行不再互相覆盖。

### 2026-10-22 `pending.json` 期望的显式决定

采纳 reviewer 要求：DB 模式下 pending 的唯一事实是 Source + `extraction_state`，
`Buffer.save()` 只在存在无 `source_id` 的历史行时才写 `pending.json`。因此
`tests/test_webui_host.py` 里两处读取 `pending.json` 的断言改为校验
`plugin.db.pending_extractions()`；`pending.json` 的读写与迁移仍由
`tests/test_capacity.py` 的 legacy 用例覆盖。此为有意变更，不是放宽断言。

### 2026-10-22 明确延后：backpressure 与批次公平性

Issue #12 设计里的两项调度增强本 PR 不做，按评审要求在此显式延后：

- `backpressure` 目前是决策令牌，驱动批次上限与强制抽取，不丢弃观测；
  真正“暂停/延后摄入”会改变消息写入时序，需要独立 issue 评估，避免在
  容量治理 PR 里混入新的丢数据风险。
- `_split_topics()` 仍按同会话同话题分桶、按桶大小排序；按会话轮转的公平
  调度需要持久化游标，同样留作后续 issue。

### 2026-10-22 Trace 软阈值

`trace_soft` 原先复用 `trace_saturated_age_seconds`，年龄维度没有独立的
软阶段。新增 `trace_pressured_age_seconds`（默认 3 天），`trace_soft` 改用
它，年龄只触发 `PRESSURED`，7 天后才进入 `SATURATED` 并裁剪。
