# Generated benchmark results

This directory preserves historical generated reports and content-free Dream triage
tradeoff snapshots. They are reproducibility artifacts, not production telemetry.
The old `latest.md` contains legacy fixture-weight/composite/character labels and
is historical, not the current regression gate. Corrected memory evaluation
writes a new ignored `.tmp/benchmarks/<run>/` directory; its fixed baseline is
`../data/memory_baseline.json`. Do not overwrite historical snapshots.

本目录保留历史生成报告及无正文的 Dream 分诊快照，不是生产遥测。
旧 latest.md 的样本权重、综合分和字数标签属于历史，不能作为当前回归门槛。
修正后的记忆评测写入新的忽略运行目录，固定基线位于上述 data 路径；不覆盖历史快照。

## Canonical files

| File | Role | Expected to change? |
|---|---|---|
| `dream_tradeoff.md` | Canonical human-readable report; generated by `benchmarks/dream_tradeoff.py` | Derived; do not hand-edit |
| `dream_tradeoff.json` | Canonical aggregate: comparison and all target snapshots | Rebuilt with the report |
| `dream_tradeoff_cc814ce.json` | Historical pre-optimization baseline | Immutable; re-record as a new dated file |
| `dream_tradeoff_d9fc248.json` | Historical merged implementation | Immutable; re-record as a new dated file |
| `dream_tradeoff_current.json` | Snapshot of the current checkout | Regenerate after relevant changes |
| `../data/dream_tradeoff_corpus.jsonl` | Frozen synthetic corpus | Change only with a new snapshot set and report |

The aggregate and the Markdown report are derived from the three per-target
snapshots. The `current` snapshot is the only one expected to change as the tree
evolves; `cc814ce` and `d9fc248` are audit history.

## Regeneration

Regenerate only the current checkout:

```bash
python benchmarks/dream_eval.py --repo . --label current \
  --output benchmarks/results/dream_tradeoff_current.json
```

Then rebuild the aggregate and the report from all three snapshots:

```bash
python benchmarks/dream_tradeoff.py \
  --input cc814ce=benchmarks/results/dream_tradeoff_cc814ce.json \
  --input d9fc248=benchmarks/results/dream_tradeoff_d9fc248.json \
  --input current=benchmarks/results/dream_tradeoff_current.json \
  --baseline cc814ce \
  --target-label d9fc248 \
  --output-json benchmarks/results/dream_tradeoff.json \
  --output-md benchmarks/results/dream_tradeoff.md
```

Do not regenerate `cc814ce` or `d9fc248` in place. If a baseline must be
re-recorded, add a new file with a date/revision suffix, keep the old file, and
state why in the report or PR.

## Platform metadata

`environment.platform` records where the snapshot was produced. The committed
snapshots were produced on `win32` (`environment.platform=win32`); this is
historical provenance, not a cross-platform assertion. The harness uses an
in-memory SQLite store, a fixed clock and a deterministic provider, so the counts
are platform-independent; CI on Linux should reproduce them. If a
platform-specific difference appears, record a new snapshot rather than editing
an old one.

## Caveat

The corpus is synthetic and the provider returns recorded outputs. These are not
production measurements; do not present them as live memory quality or live
model cost. The README table and the report carry the same caveat.
